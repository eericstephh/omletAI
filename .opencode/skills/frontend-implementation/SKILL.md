# Frontend implementation quality

## When to use
Use when turning design into working UI in an existing codebase.

## Workflow
1. Inspect the stack, routing, styling, state, and test conventions before coding.
2. Use semantic HTML/native platform controls and reuse existing primitives.
3. Keep component boundaries cohesive and avoid premature abstraction.
4. Implement actual state, loading, error, disabled, and success behavior.
5. Run available type, lint, test, and build checks; report what was not run.

## Expected outputs
- Implementation plan
- Changed components/routes
- Verification evidence
- Known limitations

## Avoid
- Replacing behavior with static markup
- Adding dependencies without a clear need

## Done when
- The recommendations connect to the actual product goal and user task.
- Important assumptions and unverified claims are explicitly labeled.
- The result is specific enough to implement or evaluate.
