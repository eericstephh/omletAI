# Design system architecture

## When to use
Use for multi-screen products or teams needing consistent reusable UI.

## Workflow
1. Inventory current patterns, repeated components, and inconsistency costs.
2. Define foundations, components, variants, states, composition rules, and contribution ownership.
3. Prioritize components by frequency, user impact, and implementation cost.
4. Specify behavior and accessibility contracts, not just appearance.
5. Adopt incrementally through representative screens and measure consistency improvements.

## Expected outputs
- System map
- Component inventory
- Governance rules
- Adoption plan

## Avoid
- Building a huge library before real use cases exist
- Treating the design system as a static style guide only

## Done when
- The recommendations connect to the actual product goal and user task.
- Important assumptions and unverified claims are explicitly labeled.
- The result is specific enough to implement or evaluate.
