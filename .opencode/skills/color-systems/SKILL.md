# Color systems and semantic color

## When to use
Use when building a brand palette, UI tokens, or light/dark themes.

## Workflow
1. Define brand, neutral, surface, text, border, focus, and status roles separately.
2. Choose colors for meaning and hierarchy; do not use color as the only signal.
3. Check text and component contrast for relevant states and sizes.
4. Define hover, pressed, selected, disabled, error, success, and focus treatments.
5. Test palette behavior in both themes and with real content.

## Expected outputs
- Semantic palette
- State-color rules
- Contrast risks
- Theme mapping

## Avoid
- A palette of attractive swatches without semantic roles
- Red/green-only status communication

## Done when
- The recommendations connect to the actual product goal and user task.
- Important assumptions and unverified claims are explicitly labeled.
- The result is specific enough to implement or evaluate.
