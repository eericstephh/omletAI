# Microinteractions and motion design

## When to use
Use when motion can clarify state, continuity, or cause and effect.

## Workflow
1. Give each animation a purpose: feedback, orientation, continuity, or hierarchy.
2. Specify trigger, duration range, easing intent, start/end state, and interruption behavior.
3. Respect reduced-motion preferences and avoid motion that blocks task completion.
4. Keep repeated transitions consistent and use motion sparingly in dense workflows.
5. Check performance on target devices and provide non-animated equivalents when needed.

## Expected outputs
- Motion principles
- Transition specs
- Reduced-motion behavior
- Performance risks

## Avoid
- Animation for decoration alone
- Long or looping motion that competes with content

## Done when
- The recommendations connect to the actual product goal and user task.
- Important assumptions and unverified claims are explicitly labeled.
- The result is specific enough to implement or evaluate.
