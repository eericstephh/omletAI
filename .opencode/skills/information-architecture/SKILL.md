# Information architecture and navigation

## When to use
Use when organizing pages, features, content, or navigation.

## Workflow
1. Inventory content and user tasks before choosing a menu structure.
2. Group items by user mental model and distinguish primary, secondary, and contextual actions.
3. Use clear labels; avoid internal team terminology in user-facing navigation.
4. Define hierarchy, route relationships, breadcrumbs/search needs, and responsive navigation behavior.
5. Check whether users can predict where an item lives and recover from a wrong turn.

## Expected outputs
- Sitemap or hierarchy
- Navigation model
- Labeling decisions
- Findability test tasks

## Avoid
- Navigation organized only around org charts
- Hiding essential destinations behind ambiguous icons

## Done when
- The recommendations connect to the actual product goal and user task.
- Important assumptions and unverified claims are explicitly labeled.
- The result is specific enough to implement or evaluate.
