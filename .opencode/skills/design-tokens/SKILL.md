# Design tokens and theming

## When to use
Use when centralizing visual decisions across screens and components.

## Workflow
1. Inspect existing tokens and actual usage before creating new names.
2. Separate primitive values from semantic aliases and component-specific tokens.
3. Define naming that describes role, not a temporary visual value.
4. Map light/dark themes and high-contrast/focus needs where relevant.
5. Document migration, deprecation, and token usage; avoid unused token sprawl.

## Expected outputs
- Token taxonomy
- Theme mapping
- Migration plan
- Usage examples

## Avoid
- Duplicated values with inconsistent names
- Tokenizing every isolated value without a reuse case

## Done when
- The recommendations connect to the actual product goal and user task.
- Important assumptions and unverified claims are explicitly labeled.
- The result is specific enough to implement or evaluate.
