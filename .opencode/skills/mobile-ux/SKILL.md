# Mobile app UX

## When to use
Use for native or mobile-first application screens.

## Workflow
1. Respect platform conventions while maintaining product identity.
2. Prioritize thumb reach, touch targets, safe areas, keyboard interaction, and interruption recovery.
3. Handle permission requests in context and preserve work across app lifecycle changes.
4. Make navigation and back behavior predictable.
5. Consider offline/slow network, battery/performance constraints, and one-handed use.

## Expected outputs
- Mobile screen rules
- Touch and keyboard states
- Lifecycle/offline cases
- Platform-specific considerations

## Avoid
- Shrinking desktop layouts into mobile screens
- Tiny controls or hidden gestures with no discovery

## Done when
- The recommendations connect to the actual product goal and user task.
- Important assumptions and unverified claims are explicitly labeled.
- The result is specific enough to implement or evaluate.
