# Navigation patterns

## When to use
Use when designing top bars, sidebars, tabs, breadcrumbs, or mobile navigation.

## Workflow
1. Match navigation pattern to information hierarchy and task frequency.
2. Differentiate navigation from actions and settings.
3. Show current location clearly and preserve orientation across nested screens.
4. Define narrow-screen adaptation, keyboard behavior, and overflow handling.
5. Use labels that are understandable without relying on icon interpretation.

## Expected outputs
- Navigation pattern rationale
- Active/hover/focus states
- Responsive rules
- Findability checks

## Avoid
- Too many competing navigation systems
- Tabs used for unrelated destinations

## Done when
- The recommendations connect to the actual product goal and user task.
- Important assumptions and unverified claims are explicitly labeled.
- The result is specific enough to implement or evaluate.
