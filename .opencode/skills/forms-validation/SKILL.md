# Forms, validation, and input UX

## When to use
Use for sign-up, settings, checkout, search, and data entry.

## Workflow
1. Ask only for information necessary for the task and explain non-obvious requests.
2. Group fields logically, use persistent labels, and choose appropriate input types.
3. Validate at the right time with specific, actionable error messages.
4. Preserve user input after errors and place errors where users can find them.
5. Support keyboard, autofill, mobile keyboards, required/optional clarity, and success confirmation.

## Expected outputs
- Field specification
- Validation timing and messages
- Error/success states
- Accessibility checklist

## Avoid
- Placeholder-only labels
- Generic 'invalid input' errors
- Clearing the whole form after a recoverable error

## Done when
- The recommendations connect to the actual product goal and user task.
- Important assumptions and unverified claims are explicitly labeled.
- The result is specific enough to implement or evaluate.
