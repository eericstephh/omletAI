# Search, filters, and sorting

## When to use
Use for catalogs, tables, content libraries, and complex data discovery.

## Workflow
1. Match search to user vocabulary and explain scope when it is not obvious.
2. Make active filters, result counts, sorting, and reset behavior visible.
3. Preserve state when users open an item and return, where feasible.
4. Design no-results, partial-match, loading, and failed-search states.
5. Support keyboard operation and narrow-screen filter management.

## Expected outputs
- Search/filter interaction spec
- State matrix
- No-results behavior
- Keyboard/responsive checks

## Avoid
- Filters that silently reset
- Unclear difference between filtering and sorting

## Done when
- The recommendations connect to the actual product goal and user task.
- Important assumptions and unverified claims are explicitly labeled.
- The result is specific enough to implement or evaluate.
