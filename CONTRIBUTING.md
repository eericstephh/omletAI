# Contributing

Contributions should make the kit more useful in real product work.

## Skill contribution checklist
- Give the skill one clear responsibility.
- Include when to use it and when not to use it.
- Provide an actionable workflow, not vague encouragement.
- Define concrete outputs and review criteria.
- Avoid duplicating another skill; link to related skills instead.
- Do not assume browser, screenshot, or device tools exist.
- Do not claim standards compliance without checks and evidence.
- Keep examples framework-neutral unless the skill is explicitly platform-specific.

## Pull requests
Describe the problem, intended users, files changed, tradeoffs, and how you validated the changes.
