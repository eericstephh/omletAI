# Design-to-development handoff

## When to use
Use when design decisions must be implemented consistently by an engineer or coding agent.

## Workflow
1. Specify layout rules, tokens, typography, states, behavior, breakpoints, and content constraints.
2. Describe component variants and interaction transitions, not just screenshots.
3. Call out asset dimensions, formats, naming, and licensing where relevant.
4. Document edge cases, accessibility requirements, and acceptance criteria.
5. Keep handoff concise and implementation-oriented; avoid details the codebase already makes obvious.

## Expected outputs
- Implementation spec
- Component/state matrix
- Acceptance criteria
- Open questions

## Avoid
- Pixel-only specs without responsive rules
- Ambiguous interaction behavior

## Done when
- The recommendations connect to the actual product goal and user task.
- Important assumptions and unverified claims are explicitly labeled.
- The result is specific enough to implement or evaluate.
