# Interaction design and feedback

## When to use
Use for controls, transitions, editing tools, and complex interactions.

## Workflow
1. Make affordances, available actions, and current state discoverable.
2. Provide immediate, proportionate feedback for user actions.
3. Prevent accidental destructive actions and provide undo or recovery when feasible.
4. Define keyboard, pointer, touch, and focus behavior where relevant.
5. Specify transition states and failure behavior, not just the static endpoint.

## Expected outputs
- Interaction specification
- State transition list
- Feedback rules
- Edge-case behavior

## Avoid
- Clickable-looking elements that do nothing
- Feedback that is delayed, vague, or absent

## Done when
- The recommendations connect to the actual product goal and user task.
- Important assumptions and unverified claims are explicitly labeled.
- The result is specific enough to implement or evaluate.
