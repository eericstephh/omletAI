# User journeys and service flows

## When to use
Use for multi-step tasks, cross-screen experiences, and onboarding.

## Workflow
1. Choose one user and one scenario; keep the journey bounded.
2. Map stages, user actions, questions, emotions only if evidence supports them, and system touchpoints.
3. Mark friction, waiting, handoffs, recovery paths, and moments of uncertainty.
4. Identify the highest-impact breakdowns and design opportunities.
5. Translate opportunities into prioritized changes and validation criteria.

## Expected outputs
- Journey map
- Friction points
- Opportunity backlog
- Critical moments

## Avoid
- A decorative journey diagram without actionable implications
- Claiming emotional states as research facts without evidence

## Done when
- The recommendations connect to the actual product goal and user task.
- Important assumptions and unverified claims are explicitly labeled.
- The result is specific enough to implement or evaluate.
