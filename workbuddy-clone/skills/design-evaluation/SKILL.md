# Design evaluation and acceptance criteria

## When to use
Use when deciding whether a design is ready for implementation or release.

## Workflow
1. Translate product goals into observable user and interface outcomes.
2. Cover core tasks, edge states, accessibility, responsive behavior, and consistency.
3. Distinguish must-pass requirements from quality improvements.
4. Specify how each criterion can be checked and what evidence counts.
5. Revisit criteria when constraints change instead of silently lowering the bar.

## Expected outputs
- Acceptance checklist
- Risk-weighted release gates
- Evidence requirements
- Known gaps

## Avoid
- Subjective goals with no observable test
- Marking unchecked items as complete

## Done when
- The recommendations connect to the actual product goal and user task.
- Important assumptions and unverified claims are explicitly labeled.
- The result is specific enough to implement or evaluate.
