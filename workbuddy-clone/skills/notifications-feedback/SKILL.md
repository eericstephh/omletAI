# Notifications and system feedback

## When to use
Use for toasts, banners, alerts, progress, and status messages.

## Workflow
1. Choose the least disruptive feedback that matches urgency and consequence.
2. Make messages specific and actionable; keep critical errors persistent until understood where appropriate.
3. Do not use toast-only feedback for essential information users may miss.
4. Announce relevant status changes accessibly and avoid repeated noisy announcements.
5. Define dismissal, timeout, stacking, and recovery behavior.

## Expected outputs
- Feedback pattern rules
- Message copy
- Timing/dismissal rules
- Accessibility behavior

## Avoid
- Success messages with no useful information
- Transient alerts for irreversible or critical outcomes

## Done when
- The recommendations connect to the actual product goal and user task.
- Important assumptions and unverified claims are explicitly labeled.
- The result is specific enough to implement or evaluate.
