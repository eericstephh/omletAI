# Product framing and design brief

## When to use
Use before a substantial new feature, product, or redesign.

## Workflow
1. Identify primary user, context, desired outcome, and the task they are trying to complete.
2. Separate user value, business value, and technical constraints; call out conflicts.
3. Define the core use case, non-goals, assumptions, dependencies, and success signals.
4. Translate the brief into 3–7 testable design acceptance criteria.
5. Ask only for missing information that materially changes the solution; otherwise document assumptions.

## Expected outputs
- A concise design brief
- Primary task and user outcome
- Assumptions and risks
- Acceptance criteria

## Avoid
- A vague aesthetic brief without a user or task
- Success metrics presented as known facts when they are only proposals

## Done when
- The recommendations connect to the actual product goal and user task.
- Important assumptions and unverified claims are explicitly labeled.
- The result is specific enough to implement or evaluate.
