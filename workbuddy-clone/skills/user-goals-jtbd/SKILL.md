# User goals and jobs-to-be-done

## When to use
Use when the interface needs to support a specific motivation or recurring task.

## Workflow
1. Describe the situation that triggers the task, the progress the user wants, and the obstacles they face.
2. Map functional, emotional, and social dimensions only when relevant.
3. Identify the user's current workaround and what makes it costly or confusing.
4. Turn goals into interface requirements and observable task completion criteria.
5. Do not fabricate research; label inferred jobs as hypotheses to validate.

## Expected outputs
- Job statement
- Top user goals
- Friction hypotheses
- Validation questions

## Avoid
- Personas based on stereotypes
- Treating a demographic label as a user need

## Done when
- The recommendations connect to the actual product goal and user task.
- Important assumptions and unverified claims are explicitly labeled.
- The result is specific enough to implement or evaluate.
