# SaaS and web application UX

## When to use
Use for multi-user tools, settings-heavy products, and subscription software.

## Workflow
1. Clarify workspace, project, account, and personal settings boundaries.
2. Make permissions, plan limits, billing, and irreversible actions transparent.
3. Design tables, filters, search, pagination, bulk actions, and empty states for real workloads.
4. Provide save status, unsaved-change protection, and reliable recovery.
5. Keep marketing promises aligned with actual product behavior.

## Expected outputs
- Core workflow map
- Settings and permissions model
- Data-heavy states
- Trust and recovery checks

## Avoid
- Decorative dashboards with no useful decision support
- Hiding plan limits or consequences

## Done when
- The recommendations connect to the actual product goal and user task.
- Important assumptions and unverified claims are explicitly labeled.
- The result is specific enough to implement or evaluate.
