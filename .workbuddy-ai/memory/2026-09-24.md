### New engine axes (real render code, shared renderer)
- `model/SubtitleTemplate.kt` — new `enum ProgressBarShape { STRAIGHT, WAVE }` + `ProgressBarSpec.shape`
  (default `STRAIGHT`), round-tripped in `toJson`/`fromJson`.
- `model/WordMotionKind.kt` — `CaptionBackgroundKind.FILMSTRIP("نوار فیلم")` + `engineTypeString`
  `"filmstrip"`.
- `db/EditorStateJson.kt` — `shape` round-trip so a saved project keeps the wave.
- `export/CaptionRenderer.kt` — pure JVM-testable wave math (`WAVE_CYCLE_MS` 3600,
  `waveOffsetY`, `wavePhaseAt`) + `drawWaveAccent`/`wavePath`; the track and fill share ONE phase so
  the fill grows along the same wave. `FILMSTRIP` background = dark plate + two rows of round-rect
  perforations, hole count capped at 20 (no blur/shader → flat per-frame cost).
- `model/template/JsonTemplateMapper.kt` + `assets/subtitle_templates.json` — rows `wave_accent`
  («موج رنگی») and `filmstrip_frame` («نوار فیلم»); catalog **17 → 19**.

### ⚠️ Real bug the tests caught (do not lose this)
`JsonTemplateMapper.mapMotion` has **TWO** `when (hl)` branches keyed on the highlight type string,
and adding a highlight type requires updating **both**:
1. the `kind` branch (~line 365) — `"colorchange" | "box" | "progressbar"` → `HIGHLIGHT_COLOR`;
2. the `reveal` branch (~line 399) — the same three strings → `WordRevealMode.HIGHLIGHT`.

`"waveaccent"` was added to the `progressBar` spec mapping but **not** to these two, so the template
compiled, parsed, mapped a WAVE bar — and `motionKind` silently came out `NONE`, i.e. **no word
highlight at all**. Caught by `JsonTemplateMapperTest`, not by the build. This is bug class #1 in its
purest form: a new field wired into one consumer while a second `when` quietly drops it.
