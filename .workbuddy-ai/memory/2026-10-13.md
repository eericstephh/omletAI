# 2026-10-13 (7) — AUDIT: PiP media overlays have NO renderer (blocks the mask brief)

Read-only recon for the "PiP Overlay with Shape Masks" brief. **Finding: the feature's
foundation does not exist.** `VideoOverlay` (the PiP media overlay model) is
**timeline-only metadata**.

## Evidence (all via grep, no inference)

- `VideoOverlay` is declared at `model/EditorUiState.kt:668` with `clipId`, `positionX`,
  `positionY`, `scale`, `opacity`, `uri`, `isVideo`, `startTimeMs`, `endTimeMs`, `label`.
- **Every one of its rendering-relevant fields has zero consumers:**
  `overlay.uri` and `overlay.isVideo` appear ONLY in `db/EditorStateJson.kt`
  (`mediaOverlaysToJson` / `mediaOverlaysFromJson`). `positionX` / `positionY` / `scale` /
  `opacity` appear nowhere outside the codec either.
- **Only two `ExoPlayer.Builder` sites exist in the whole app**: the main preview player
  (`EditorScreen.kt:466`) and the audio stems (`AudioMixerPlayer.kt:113`). There is **no
  player for overlay media**.
- **`mediaOverlays` never appears anywhere under `export/`.** Its only homes are the JSON
  codec, `ProjectEntity.mediaOverlaysJson` (Room column), `VideoProject`, `ProjectRepository`,
  `SampleProjectSeeder`, `ImportVideoViewModel` and `EditorViewModel` (load/save).
- `EditorScreen` hands `uiState.overlays` to **`EditorTimeline` only** (line 4103) — the
  lane chips. All overlay *rendering* in the screen is `textOverlays` (`TextOverlay`), a
  different model.
- `VideoExportEngine`'s own coverage table says it outright:
  `| Text (para) | paragraph / decorative overlays are preview-only |`.

So: PiP overlays can be added, persisted and seen as a timeline lane — and are **never drawn
in the preview and never composited in the export**. Steps 2 and 3 of the brief ("apply
clipping in the preview canvas where overlay clips are rendered", "apply the mask onto the
overlay video frames during export") have no render target.

## What DOES render in BOTH preview and export today

`export/CaptionRenderer.kt` → `SubtitleBurnIn` → `OverlayEffect` (captions);
`TrackedOverlayRenderer` baked through `VideoFramePipeline` + `FrameOp`
(`AiExportHooks.burnTrackedOverlay`); `CanvasBackgroundOverlay`; `ProgressBarOverlay`;
`VignetteOverlay`; `GrainEffect`.

## Media3 constraint worth knowing

Media3 1.5.0 has **no public video-over-video compositing API**. `OverlayEffect` /
`TextureOverlay` / `BitmapOverlay` are **bitmap-only**. Real PiP video would need either a
custom `GlEffect`/`GlShaderProgram` with a second sampler, or a per-frame decode-and-blend
pass on the existing `FrameOp` pipeline (the precedent the tracked-overlay burn-in already
sets). Neither is small.

## Consequence

Implementing the mask layer on top of a non-existent renderer would ship this project's own
bug class 1 — "a field written but never rendered" — which `MEMORY.md` explicitly warns
against. So the direction was put to the user rather than guessed.

## Design decisions worth keeping

1. **`playbackRate` is 1.0 for EVERY effect, deliberately.** A naive chipmunk is just
   "play it faster", which desyncs A/V and multiplies against the `SpeedCurve` ramp. Every
   effect is duration-neutral; the property is declared *and asserted* so a future effect
   that changed it fails `VoiceEffectTest.every effect is duration neutral`.
2. **Only CHIPMUNK/DEEP are pure pitch.** ROBOT is ring modulation + band-pass, TELEPHONE
   is a band-pass, ECHO is a delay line — `SonicAudioProcessor` cannot express any of them.
   That is why the feature is not "set a pitch factor".
3. **Pitch is NOT routed through `PlaybackParameters.pitch`.** Doing so would put the pitch
   stage *after* the rate change in the preview but *before* it in the export. It goes
   through an explicit `SonicAudioProcessor` in the chain instead, so both renderers run
   **timbre → pitch → rate** on source-rate audio.
4. **The processors never report themselves inactive.** Media3 asks `isActive()` once at
   `configure()` and *drops* a processor that says no — so one that declined while the
   effect was NONE would be gone for the session and turning an effect on later would
   silently do nothing. Cost: one buffer copy.
5. **One `VoiceEffectPreviewBridge` per stem**, not one shared — two songs can carry
   different effects and a shared bridge would let the second overwrite the first on sync.
6. **A preset tap is one deliberate edit**, so the ViewModel pushes an undo snapshot and
   persists unconditionally; re-tapping the selected card returns before `push()`.

## Two bugs found by the work itself

- **A missing import, not a missing icon.** `Icons.Filled.RecordVoiceOver` failed to
  resolve in `ContextualToolbarSpec.kt` — the import was added in `VoiceChangerPanel.kt`
  but not there. This file imports icons **individually and alphabetically** (no wildcard),
  so a new icon needs a new line between `OpenWith` and `Speed`. First build failure.
- **A KDoc that over-claimed what the code does.** `RING_MOD_BLEND` was documented as
  preventing the modulator from nulling the signal. It does not: the multiplier is
  `(1-B) + B·sin`, so it spans `[1-2B, 1]` = `[-0.7, 1]` and still crosses zero twice per
  LFO cycle. What the blend actually buys is a shallower modulation with a **non-zero
  mean** (`1-B` = 15%, i.e. the surviving dry fraction) rather than a pure ring mod's zero
  mean. The test asserted the wrong property (`min >= 0.15`) and failed with `-0.70000005`
  — the code was right, the documentation and the assertion were wrong. Fixed all three:
  the KDoc (now a peak/trough/mean table), the inline comment, and the test (which now
  asserts peak = 1, trough = `1-2B`, mean = `1-B`). **Lesson: when a numeric assertion
  fails on a DSP, check whether the documented *claim* is the thing that is wrong.**

## Design decisions worth keeping

- **Polygons, not beziers.** `OverlayMaskGeometry.outline` returns a normalised
  `List<NormPoint>` consumed by Compose `Path` *and* `android.graphics.Path`.
  Two independent curve evaluators kept in sync "by review" is the exact failure
  mode this project keeps hitting, so parity is now structural.
- **Anchor = box top-left**, `scale` = box width / canvas width. A centre-anchor
  reading pushes the model's own `0.1/0.1/0.3` default off-screen.
- **`CANVAS_UNIT_PX = 720f`** reused, not Compose `Dp.toPx()`.
- **Export pass runs LAST** — `positionX`/`positionY`/`scale` describe the frame
  the viewer finally sees, so matting → reframe → tracking must all precede it.
- **`FrameOp` must mutate and RETURN `src`** (the pipeline recycles a returned
  bitmap that differs from the input).
- **Inversion differs per renderer by necessity:** export uses
  `Path.FillType.INVERSE_EVEN_ODD`; Compose's `PathFillType` has only
  `NonZero`/`EvenOdd` (verified via `javap` on ui-graphics 1.7.2), so the preview
  knocks the outside out with `BlendMode.DstOut` on a `CompositingStrategy.Offscreen`
  layer. Same outline, same result.

## Traps hit (three, all mine)

1. **`Modifier.weight` is a `RowScope` extension.** `ShapeChip`'s own receiver is
   a `Column`, so `Modifier.weight(1f)` inside it did not resolve. Fix: take a
   `modifier: Modifier = Modifier` param and apply `weight` at the `Row` call site.
2. **Compose has no inverse fill type** — `Unresolved reference 'InverseEvenOdd'`.
   Fix = the `DstOut` knockout above, not a fill type.
3. **A conditional `remember`** (`invertOutline` built inside an `if`) is a
   slot-table hazard when the switch toggles. Fix = one unconditional `remember`
   returning `null`.
