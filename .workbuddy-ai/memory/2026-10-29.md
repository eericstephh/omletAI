## 3. Matting temporal filter — `8ebfd3d`

`ai/MattingTemporalFilter.kt` + 13 tests. Replaced `TEMPORAL_ALPHA = 0.65` with **median of three +
scene-cut reset at 0.35**, and deliberately **no EMA on top**.

The design detail worth keeping: the first version *did* keep an adaptive EMA, and the test
`a moving edge lags exactly one frame and never trails` proved it wrong — an EMA recursing on the
previous **output** turned the median's one-frame lag into a four-frame fade (1.0 → 0.3 → 0.09). The
median already guarantees that nothing is emitted which was not a majority of the last three
measurements, so blending it with history only reintroduces the decay it just removed. **When a
stability filter has already discarded a value, do not average the result.**

Consequence to remember: the emitted mask is **binary** again, because the category mask is binary and
the EMA was the only thing producing partial alpha. Soft edges are the composition-time feather
(`MaskPostProcess.gaussianFeather`) — which is where they belonged.

Also corrected a **false KDoc** in `MediaPipeMattingEngine` claiming "threshold + soft knee so
hair/soft edges survive as partial alpha". There was never a soft knee. Classic bug class #3.

## 4. `ANALYSIS_MAX_SIDE` 720 → 512 — `a4e9109`

Not 320. At 320 a 16:9 frame becomes 320×180, i.e. a **short side of 180, below the model's 256
input**, so the segmenter stretches a starved frame up. 512 → 512×288 keeps the short side above the
model input and halves the per-frame pixel count (147k vs 291k). Pinned by
`AiMattingEngineTest.analysis bound keeps the short side at the model input`, which also asserts the
bound is a real reduction, so it cannot be quietly lowered back to 320.

`AiFrameAccuracyWiringTest` asserts the literal `maxSide = ANALYSIS_MAX_SIDE` — keeping the constant
name (only its value changed) is why that test needed no edit.

## The defect the device found — export crashed at PREPARING

`FAILED: Export failed at PREPARING`, surfaced to the user as "Video processing failed". The log
stack was fully obfuscated:

```
java.lang.IllegalStateException
  at android.graphics.Bitmap.setPixels(Bitmap.java)
  at b5.b0.invoke(...)      <- AiExportHooks$compositeMatting$2
```

**Technique worth keeping:** do not guess at an obfuscated stack — `app/build/outputs/mapping/
release/mapping.txt` is written by every release build. `grep "^[^ ].* -> b5\.b0:$"` resolved the
frame to `AiExportHooks$compositeMatting$2` in one step. The class name in the log is *sometimes*
kept (R8 keep-rules), but the lambda frames are not.

Root cause: `MaskBitmaps.applyPostProcess` applied expansion/feather/reverse with
`mask.setPixels(...)` **on the bitmap it was handed**, and its only caller passes
`BitmapFactory.decodeFile(sidecarPng)` — decoded bitmaps are **immutable**. `isNoOp` returns before
touching the bitmap, so the defect only fires once a slider is off zero. It shipped on 10-25 and was
never exercised because every prior export used the no-op path.

Fix (`2858d7c`): copy-then-write — `mask.copy(Bitmap.Config.ARGB_8888, true)`, write into the copy,
caller recycles the decoded original. Also wired the dead `shortSideOverride` through to
`MaskPostProcess.apply`. Audited **every** `setPixels` site in the app; all others target a
`createBitmap`/`copy(..., true)`. This was the only decoded-bitmap write.

## Lesson

Two of today's three defects were **dead parameters / untested paths that only a device could
expose**: the EMA that could not be tuned, and a mutability contract that no test exercised because
the test path was the no-op. `isNoOp` short-circuits are a classic hiding place — when a function has
a fast path and a slow path, the slow path is the one that is broken.
