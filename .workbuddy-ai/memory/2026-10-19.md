# 2026-10-19 — «برش» must cut the audio lane too

## Request (fa)

> دکمه برش فقط روی ویدیو اعمال میشه — برای صدا هم میخوام اعمال بشه

## Root cause

`EditorViewModel.splitClip` reshaped `project.clips` (`VideoClip`) only. A video
clip's soundtrack is a separate `AudioClip` on the "Video Audio" lane
(`originVideoClipId` = video id, seeded by `seedVideoAudioClipsIfNeeded`), so a
cut left that lane as ONE unbroken tile spanning both halves. `EditorContext
.AUDIO_SELECTED` had no `split` chip at all, and the dock's `"split"` handler
read `selectedClipId`, which is null by construction in the audio context —
so the button was a dead tap there.

## Changes

- **NEW `model/AudioClipSplit.kt`** — pure `split(clip, atTimelineMs,
  rightHalfId, rightOriginVideoClipId)`. Right half advances `clipOffsetMs` by
  the left half's length (otherwise it replays the file's beginning), keeps
  `beatData` (markers are source-time; renderer filters by offset+span), and a
  cut never introduces a fade at the join (left keeps fadeIn only, right keeps
  fadeOut only). Right half's `originVideoClipId` is retargeted at the new video
  clip — two objects on one origin would make the seeder duplicate on reload.
- **`EditorViewModel.splitClip`** now also splits the paired audio object and
  returns `Boolean` (true = cut applied). Persists `persistProjectMeta()` too,
  because audio lives in `audioClipsJson`, not the clip table.
  `splitClipMultiple` writes the audio table once per batch.
- **NEW `EditorViewModel.splitAudioClip`** — audio-context entry point. A
  paired object delegates to `splitClip(parentVideo)` (one undo step, both lanes
  stay aligned, origin invariant holds); standalone objects split directly.
  After a paired cut the selection is handed back to the left AUDIO half so the
  "one selected object" invariant is preserved.
- **NEW `notifySplitNotPossible()`** → `editorNotice`
  «نقطه برش باید داخل محدوده کلیپ باشد» instead of a silent no-op.
- **`ContextualToolbarSpec`** — `SplitAudioAction` (`id = audio_split`,
  `actionId = "split"`, label «برش») is now the FIRST chip of `AudioChips`.
- **`EditorScreen`** `"split"` handler branches on `selectedAudioClipId` first.
- Tests: new `AudioClipSplitTest` (10 cases); `ContextualToolbarSpecTest`
  updated (audio row = 6 chips; split offered by exactly CLIP + AUDIO).

## Delete (and duplicate, and drag) now follow the paired audio — 3rd request

User report: «وقتی دکمه حذف رو میزنم ویدیو پاک میشه در تایم‌لاین ولی صدا پاک نمیشه».

Root cause: `deleteClip` filtered `project.clips` only. The paired `AudioClip`
(`originVideoClipId == clipId`) survived — and `persistProjectMeta` was never
called, so even a restart would have brought the orphan tile back from
`audioClipsJson`.

Fixed the same drift on two more gestures found while auditing every mutator of
`project.clips`:
- `deleteClip` → also drops audio with `originVideoClipId == clipId`, clears the
  audio selection if it pointed at a removed object, calls `persistProjectMeta()`
  when it removed any.
- `duplicateClip` → clones the paired audio, shifted by the same delta, with
  `originVideoClipId = duplicatedClip.id` (a clone pointing at the OLD id would
  give one video two audio objects and make the seeder duplicate on reload).
- `updateClipPosition` (timeline drag) → shifts the paired audio by the same
  delta; persists meta only when an audio object actually moved (this runs per
  drag frame, so the flag matters).

**Still not synced: trim (`setClipTrim`) and speed (`setClipSpeed`).** A trim
changes the video's window but leaves the audio tile at the old span, and a
speed change changes `effectiveDurationMs` without touching `durationMs` of the
audio object. Doing those correctly needs a decision on how the audio window
maps through speed (source-time vs timeline-time), so they were left alone.

Tests: new `viewmodel/AudioLaneLifecycleWiringTest` (5 source-shape assertions:
split / delete / duplicate / drag). Ran with the 4 stale Whisper test files
parked, then restored: **BUILD SUCCESSFUL**.

APK: `dist/Omelet-1.4.0-debug-audio-delete.apk` — 122,143,507 B, zipalign OK,
debug signature OK, `classes6.dex` hash differs from the previous build (proof
the new code shipped).

## AI tools audit + frame-accuracy fix — 4th request

User: «قابلیت‌های هوش مصنوعی به جز زیرنویس خیلی ضعیف کار می‌کنن». Asked to audit + fix, and to
use a "rea" tool for CapCut reverse engineering. **No such tool exists in this environment**
(ToolSearch for rea/reverse-engineering returned nothing) — used the engine sources + the bundled
`aierix-cut-project` skill + a CapCut feature search instead.

### Root causes found

1. **Keyframe-only sampling (the big one).** `MediaMetadataRetriever.getFrameAtTime(..., OPTION_CLOSEST_SYNC)`
   in `MediaPipeMattingEngine`, `SaliencyTrackerEngine` and `VideoFramePipeline.sampleFrame` (OCR).
   That option returns only **sync frames**, so every timestamp inside one GOP decoded to the same
   picture: 20 identical masks per 2 s GOP, masks labelled with the *requested* time (lag up to half
   a GOP → cutout slides off the person), Auto Frame's trace a staircase the 1-Euro filter then
   smoothed into per-GOP jumps, OCR reading the same keyframe repeatedly. The returned bitmap also
   carried **no display rotation**, so crop/ROI coordinates were wrong on portrait sources.
2. **Mask lookup was O(files) per frame.** `AiExportHooks.maskFor` → `MattingSidecar.nearestTimestampPng`
   listed + sorted the whole sidecar directory for *every* output frame (≈600 stats × 1800 frames).
3. **Smart Highlights had no reader.** `applyHighlights` wrote `VideoClip.highlightRanges`; nothing in
   UI/export ever read it, so the tool reported success and changed nothing.
4. **Upscaler chip was locked.** `ComingSoonChipIds = setOf("upscale")` and `ToolbarTile` sets
   `enabled = !comingSoon` → the panel was unreachable although the ESRGAN pipeline is complete.
5. **Expectation gap.** Background Remove and Voice Clean only take effect at export (preview cannot
   sample the player surface; cleaned audio is swapped post-Transformer). Panels said nothing.

### Fixes

- New `ai/media/SequentialFrameSampler.kt`: one sequential MediaCodec decode, emits frames at the
  requested interval with the picture's **real PTS rebased to 0**, applies display rotation, bounds
  the frame with `maxSide`, never throws (returns 0 → caller falls back to the old retriever path).
- Matting / Auto Frame / OCR switched to it. Matting sidecar keys are now the picture PTS.
  OCR caps analysis at 1920 px (`OCR_ANALYSIS_MAX_SIDE`) so 4K no longer builds an 8K grayscale copy.
- New `export/MaskIndexMath.kt` (binary search) + a per-pass index cache in `AiExportHooks`.
- `EditorTimeline`: `HighlightRangeStrip` paints ranges on the clip tile (emerald band, alpha = score).
- `ContextualToolbar`: `ComingSoonChipIds` is now `emptySet()`.
- `AiMattingPanel` / `VoiceCleanPanel`: one-line Persian hint that the result lands in the export.

### Tests

- `ai/AiFrameAccuracyWiringTest` (4), `ui/.../AiFeatureVisibilityWiringTest` (2),
  `export/MaskIndexMathTest` (6) — all green. Ran with the 4 stale Whisper tests parked, then
