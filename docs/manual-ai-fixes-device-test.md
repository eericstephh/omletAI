# تست دستی اصلاحات AI (Auto Frame / حذف پس‌زمینه / ردیابی حرکت) — روی گوشی

APK نصب: `AICreatorStudio-v1.4.0-debug-aiFixes-2026-10-17.apk` (ریشهٔ مخزن؛ بیلد ۲۰۲۶-۱۰-۱۸، متناسب با آخرین تغییرات سورس).

```powershell
C:\android\platform-tools\adb.exe install -r .\AICreatorStudio-v1.4.0-debug-aiFixes-2026-10-17.apk
```

مسیر ورود به پنل «حذف پس‌زمینه» (روی شبیه‌ساز Pixel 8 تأیید شد):
۱) پروژه را باز کنید. ۲) روی کلیپ ویدیویی در Timeline بزنید تا انتخاب شود. ۳) در نوار ابزار پایینی، چیپ **هوشمند** را پیدا کنید (چیپ‌های دیگری مثل «برش»، «سرعت»، «ولوم»، «فیلتر» قبل از آن هستند؛ ردیف را افقی اسکرول کنید). ۴) از برگهٔ «ابزارهای هوشمند»، گزینهٔ **حذف پس‌زمینه** را بزنید.

## ثبت زمان‌بندی موتور قبل از تست‌ها

در یک پنجرهٔ جداگانه لاگ را باز کنید:

```powershell
C:\android\platform-tools\adb.exe logcat -v time -s MediaPipeMattingEngine
```

پس از هر اجرا باید یک خط جدید ظاهر شود؛ اساس قضاوت سرعت Apply همین اعداد است (پیش از اپتیمیزه هیچ عددی ثبت نمی‌شد):

```
matting pass: frames=N decode=Xms infer=Yms write=Zms
```

## سناریوها

### A. Apply اول (کلیپ کوتاه، حدود ۱۰ ثانیه) — حالت BLUR
- [ ] «اجرا» را بزنید؛ انتظار: پیشرفت با متن وضعیت فارسی نمایش داده شود.
- [ ] پس از اتمام بدون خطا ران شود؛ در لاگ خط `matting pass` ظاهر شود — اعداد را یادداشت کنید.
- [ ] نتیجه در خروجی نهایی (بخش D) بررسی می‌شود؛ ماسک در پیش‌نمایش زنده هنوز نمایش داده نمی‌شود — این محدودیت شناخته‌شده است، نه باگ.

### B. Apply دوم روی همان کلیپ
- [ ] دوباره «اجرا» بزنید؛ انتظار: زمان کل به‌طور معنادار بدتر نشود (decode/infer گرم شده). هر اجرا فریم‌ها را از نو می‌نویسد — این رفتار عادی است.
- [ ] پنل نباید امکان زدن Apply پشت هم را بدهد (رفع دکمهٔ Apply تکراری).

### C. لغو وسط اجرا
- [ ] اجرا را شروع کنید و در میانه از پنل خارج شوید/لغو کنید.
- [ ] انتظار: بدون کرش، بدون پیام «آماده است»، و در اجرای بعدی سایدکار دوباره از نو و سالم نوشته شود (سایدکار فقط پس از تأیید segmenter و metadata شروع به نوشتن می‌شود).

### D. خروجی نهایی برای هر چهار حالت
- [ ] برای هر حالت یک بار Apply بزنید و بعد از دکمهٔ «خروجی» در بالای صفحه، ویدئو نهایی را بگیرید.
- [ ] انتظار در فایل خروجی: پس‌زمینهٔ پشت سوژه بر اساس ماسک جایگزین شده باشد.
- [ ] BLUR: پس‌زمینهٔ تار.
- [ ] COLOR: پس‌زمینهٔ رنگ ثابت تیره (کد `0xFF111111`؛ انتخاب‌گر رنگ هنوز در UI نیست — محدودیت شناخته‌شده).
- [ ] IMAGE: تصویر انتخابی به‌عنوان پس‌زمینه.
- [ ] VIDEO: ویدئوی انتخابی به‌عنوان پس‌زمینه.
- [ ] TRANSPARENT: باید عمداً با پیام صریح شکست بخورد (MP4 کانال آلفا ندارد) — این رفتار صحیح است.

### E. اتوفریم
- [ ] چیپ هوشمند ← «اتوفریم»؛ اجرا و سپس خروجی بگیرید.
- [ ] انتظار: قاب در کل زمان مدت ویدئو دنبال سوژه حرکت کند و در خروجی اعمال شود (ریاضی کراپ حالا از یک منبع مشترک خوانده می‌شود).

### F. ردیابی حرکت
- [ ] چیپ هوشمند ← «ردیابی حرکت»؛ اجرا و خروجی بگیرید.
- [ ] انتظار: یکپارچگی موقعیت سوژه بین پیش‌نمایش (بخش tracked overlay) و خروجی نهایی.

## عیب‌یابی سریع

| نشانگر در لاگ/devices | معنی |
|---|---|
| `failed: blank mask` | ماسک خالی — شکست بلند. ویدئوی نمونه و زمان را یادداشت کنید و «دوباره سعی کنید» بزنید |
| حذف خط از لاگ `matting pass` برای هر Apply | برای هر اجرا باید فقط یک خط باشد؛ اگر تکراری شد، مسیر Apply مکرر را در UI دیده‌اید (باگ، گزارش کنید) |
| ماسک جاافتاده/ناخوانا در خروجی | مسیر PNG در manifest سایدکار؛ لاگ بخش write را بررسی کنید |
| خطای «دانلود مدل» یا «بررسی صحت مدل ناموفق بود» | دکمهٔ «دانلود مدل» را بزنید و «دوباره سعی کنید» را اجرا کنید (پیام‌های فارسی جدیدِ پنل) |
