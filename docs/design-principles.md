# Design Principles

1. **Purpose before polish:** identify the user task before choosing style.
2. **Hierarchy over decoration:** emphasis should communicate priority.
3. **Consistency with flexibility:** reuse patterns but allow justified exceptions.
4. **Real states:** design for loading, empty, error, disabled, success, and recovery.
5. **Accessible by default:** semantic structure, keyboard support, contrast, and readable content.
6. **Responsive by intent:** reflow based on content and task needs.
7. **Honest feedback:** explain what happened and what can happen next.
8. **Evidence over confidence:** distinguish observed facts from hypotheses.
9. **Respect the codebase:** inspect existing architecture and minimize unnecessary changes.
10. **Verify, then report:** never claim a test or visual check passed without evidence.
